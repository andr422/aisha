Первым делом

Если прямо сейчас что-то сломалось

Данные почти никогда не теряются мгновенно. Занятие живёт на планшете до нажатия «Отправить данные», а после — в очереди внутри планшета, пока не уйдёт в таблицу. Поэтому первое правило: не чистите данные браузера и не удаляйте приложение, пока не убедились, что всё уехало.

  1. Посмотрите на строчку под кнопками на «Сборе». Она честно говорит состояние: «Ожидают отправки», «Не доставлено», «Ушло без подтверждения». Нажатие на неё пробует отправить прямо сейчас и называет причину словами.
  2. Откройте приложение при интернете и подождите минуту. Очередь досылается сама: при запуске, при появлении сети и раз в 60 секунд.
  3. Если экран выглядит неправильно (пропали кнопки, старый вид) — закройте приложение полностью и откройте заново при интернете. Обычно это застрявшая старая версия в кэше.
  4. Если нужно откатить мою правку — в GitHub у каждого файла есть история версий: откройте файл → History → нужную версию → кнопка восстановления. Ничего не пропадает навсегда.

Единственное действие, которое реально теряет данные: удаление цели или протокола на «Настройке», пока занятие не отправлено. Приложение предупредит, но восстановить будет нечем. Сначала «Отправить данные», потом правки.

Устройство

Из чего состоит приложение

Это не программа, которую устанавливают, а набор файлов на GitHub Pages. Браузер скачивает их и показывает. Никакого «сервера приложения» нет — данные живут в планшете, а в Google-таблицу их отправляет отдельный скрипт.

Анатомия

Как устроен один файл

Каждая страница — один файл, внутри которого три слоя. Это важно понимать: когда я говорю «правка в стилях» или «правка в логике», речь про разные части одного и того же файла.

СлойГде в файлеЗа что отвечаетНасколько опасно править
Стили
<style>		 Сверху, первые несколько сотен строк Как выглядит: цвета, размеры, отступы, что видно, а что скрыто Безопасно. Максимум — станет некрасиво, данные не пострадают
Разметка
обычный текст с тегами		 В середине, после стилей Из чего состоит страница: заголовки, кнопки, окошки Средне. Если удалить элемент, логика может искать его и не найти
Логика
<script>		 Внизу, самая большая часть Что происходит при нажатиях, как считается, куда сохраняется Осторожно. Здесь живут данные

Логика написана функциями. Функция — это именованный кусок работы: «посчитать проценты», «отправить занятие», «нарисовать список целей». Когда что-то работает неправильно, почти всегда виновата одна конкретная функция — и её можно найти по имени.

Как искать в файле. Откройте файл на GitHub и нажмите клавишу / (или Ctrl+F / ⌘F) — появится поиск по тексту. Введите имя функции из раздела «Карта функций», например function increment, и попадёте прямо на неё. Номера строк в этом разборе — ориентир на август 2026; после правок они сдвигаются, а имена остаются.

Русские комментарии в коде — это пояснения для человека, они начинаются с //. Я пишу в них не «что» (это видно из кода), а «почему»: почему сделано именно так и что сломается, если поменять. Это ваша главная подсказка при чтении.

Хранение

Где лежат данные

Внутри планшета два хранилища. Оба принадлежат браузеру и относятся к конкретному адресу сайта.

localStorage — простые записи

Текст «ключ → значение». Здесь настройки и всё, что нужно быстро: протоколы, цели, счётчики текущего занятия, журналы ABC и частоты.

КлючЧто хранит
protocol1_titleНазвание первого протокола. Второго — protocol2_title, и так далее
protocol1_goal2Название второй цели первого протокола
..._introDate / ..._masteryDateДаты введения и освоения этой цели
..._genStim / _genPlace / _genPeopleПлан генерализации: материалы, места, люди
..._genLogФакт генерализации: какие из девяти проб пройдены и когда
..._coldProbeПротокол помечен как холодная проба

aba_block_keysКому эти счётчики принадлежат: «протокол ‖ имя цели». Благодаря этому числа не съезжают на чужие цели

abc_* / freq_*Списки и журналы вкладок ABC и «Частота». Списки поведений у них РАЗНЫЕ: abc_behaviors и freq_behaviors (разделены 20.08.2026; при первом открытии «Частоты» список один раз копируется из ABC)

aba_child_<id>Свёрнутый набор данных других детей
aba_templatesШаблоны протоколов, сохранённые на этом планшете

Ключевая идея всей архитектуры. Активен всегда ровно один ребёнок, и его данные лежат под простыми именами без номера ребёнка: protocol1_title, а не ребёнок7_protocol1_title. При переключении ребёнка приложение сворачивает весь набор в aba_child_<id> и разворачивает набор другого. Поэтому весь остальной код не знает про детей вообще — он просто читает protocol1_title. Это сильно упростило код, но означает: переключение ребёнка — операция, при которой данные физически переезжают, и делать её на середине занятия не стоит.

IndexedDB — хранилище побольше

База aba_db с двумя полками:

  • history — история замеров по каждому ребёнку (ключ aba_history::<id>, до 200 занятий) и PDF-файлы протоколов.
  • send_queue — очередь отправки. Каждый пакет сначала кладётся сюда, и только потом уходит в Google. Поэтому отключение интернета посреди занятия не теряет ничего.

Хранилище привязано к браузеру. На айфоне у Chrome, Safari и приложения с домашнего экрана — три разных хранилища. Данные, набранные в браузере, приложение с домашнего экрана не видит и отправить не может. Отсюда правило: работать только с иконки на домашнем экране.

Ключевые детали этого пути:

  • Сначала очередь, потом сеть. Пакет считается сохранённым, как только лёг в очередь. Даже если интернет пропал, данные не потеряны.
  • Доставка подтверждается честно. Приложение читает ответ скрипта и удаляет пакет из очереди только получив «ок». Если ответа нет — пакет остаётся и будет досылаться.
  • У каждого пакета свой номер (uid). Скрипт помнит 300 последних и на повтор отвечает «уже принято». Поэтому повторные отправки не создают дублей в таблице.
  • Счётчики обнуляются только после успешной постановки в очередь. Если что-то пошло не так, занятие остаётся на экране, и его можно отправить снова.

Подробности

Механизмы по задачам

Процент и освоение

Процент считается в updatePercentages по формуле «+» ÷ («+» + «P» + «−»). Подсказки и ошибки одинаково в знаменателе — это осознанное решение: процент показывает самостоятельность.

Критерий освоения — три последних замера ≥80%, функция checkMastery. Важная тонкость, которую мы недавно чинили: считаются замеры, а не календарные занятия. Занятия, где цель не отрабатывали, просто не в счёт — их отбрасывает goalMeasurements. Когда критерий выполнен, markMasteredGoals сама проставляет дату освоения (вписанную вручную не трогает).

История и почему она по именам целей

Каждое занятие хранит не только проценты, но и имена целей (goalNames). Поэтому снятая с работы цель не теряется в истории, а смена набора целей не сдвигает старые данные. Чтение — goalValueAt, серия по цели — goalSeries.

Внутри занятия данные разложены по номеру протокола: первый элемент — протокол 1, второй — протокол 2. Если протокол пропущен (все цели ушли на генерализацию), для него кладётся пустое место, чтобы нумерация не поехала. Это чинили в июле — иначе проценты «съезжали» на чужие цели.

Счётчики не должны съезжать

Счётчики хранятся списком по порядку целей на экране. Если список целей изменится, числа окажутся на чужих целях. Защита — aba_block_keys: рядом со счётчиками пишется, какой цели каждый принадлежит, а realignProgressToBlocks при каждой отрисовке раскладывает всё по местам. Если цель убрали, а по ней были нажатия, приложение честно скажет, что эти данные пропали.

Генерализация

Освоенная цель уходит из списка занятия в свёрнутый блок внизу (renderGeneralization). Там девять проб: три материала, три места, три человека. Отметка — toggleGenProbe, хранится в ..._genLog. В таблицу уходят только изменения с прошлой отправки (collectGenRows), поэтому лист не засоряется повторами.

Холодные пробы

Галочка на протоколе (..._coldProbe) означает: одна попытка за занятие. applyColdProbeLocks следит за суммой трёх счётчиков цели и, как только она стала больше нуля, закрывает кнопки. Открываются обратно отменой, очисткой цели или отправкой занятия.

Подсказки на экране

Весь тур — в tour.js. Тексты шагов лежат в SCRIPTS, отдельно для каждой страницы: sel — что подсветить, title и text — что написать. Это самое простое место для самостоятельной правки текста.

Рядом объект VERSIONS — номер версии подсказок для каждой страницы. Подняли номер → подсказки один раз покажутся заново всем, кто их уже видел. Не подняли → новое увидят только новички.

Кэш и обновления

sw.js хранит копии файлов в планшете, чтобы приложение работало без интернета. Строка CACHE_NAME — это версия. Пока номер не изменился, планшет считает, что у него всё свежее, и новые файлы не скачает. Отсюда главное правило правок — следующий раздел.

Два адреса

Куда на самом деле уходят данные с августа 2026

Раньше занятие уезжало в одно место — в Google-таблицу. Теперь в два: в ту же таблицу и на наш собственный сервер. Оба получают одинаковый пакет с одним и тем же номером, поэтому потом можно сверить, что где лежит.

Зачем так: сервер новый, и пока он не отработал достаточно, отключать таблицу нельзя — она остаётся тем, чему верим. Двойная запись стоит дёшево и позволяет проверять сервер на настоящей работе, ничем не рискуя.

Как это выглядит в коде. Рядом со старым адресом (SESSION_ENDPOINT) появился второй — SERVER_ENDPOINT. Функция packetTargets отдаёт оба, и очередь кладёт две копии одной записью: либо в очередь попадёт всё, либо ничего.

Чтобы выключить сервер и вернуться к одной таблице, достаточно оставить SERVER_ENDPOINT пустой строкой в трёх файлах: «Сбор», ABC, «Частота».

Важная деталь, которую легко потерять при правках. Раньше сбой сети обрывал всю рассылку очереди. С двумя адресами это стало опасно: лежачий сервер заблокировал бы и отправку в таблицу. Теперь недоступный адрес запоминается (deadEndpoints) и пропускается только он, а остальные пакеты уходят как обычно.

Ключ в адресе сервера (?k=…) — это не защита данных, а замок от случайных запросов из интернета. Он лежит в коде и виден любому, у кого в руках планшет; настоящий вход по логину появится позже.

Что делать, если данные не доходят до сервера, но доходят в таблицу: почти всегда это старый код на планшете. Закройте приложение через переключатель приложений и откройте заново — обновление подхватывается только при полном перезапуске.

Оформление

Почему цвета живут отдельно от страниц

Раньше каждый цвет был вписан прямо в страницу числом вроде #0e7490. Пока тема одна, это удобно. Как только их стало шесть, выяснилось неприятное: сменить фон легко, а кнопки, чипы и подсказки остаются прежними — получается каша.

Поэтому все цвета, скругления, тени и шрифты вынесены в theme.css под именами: --card — фон карточки, --accent — основной цвет действия, --ok, --prompt, --err — цвета исходов пробы (сам / с подсказкой / ошибка). Страницы больше не знают цветов, они знают только имена. Тема — это набор новых значений для тех же имён.

Правило на будущее: если добавляете что-то новое на страницу, не пишите цвет числом. Возьмите подходящее имя из theme.css — иначе в тёмной теме ваш кусок останется светлым, и это заметят не сразу.

Размеры рабочей зоны тоже там: --tap-font (знак «+»), --pct-font (процент у цели). Их можно крутить, не разбирая код страницы. Что изменилось 20.08.2026: высота кнопок теперь задана прямо в страницах — 48 px и там, и на «Частоте», — а --tap-pad больше ни на что не влияет. Ширина «P/−» на «Сборе» — первая колонка в правиле .btn-set, сейчас 108 px.

Две кнопки вместо трёх (20.08.2026)

На «Сборе» у цели теперь два элемента управления: узкая «P/−» слева и широкая «+» справа — та же сетка, что у карточки поведения на «Частоте». Ошибку выбирают в окне, которое открывает долгое нажатие «P/−»: там же, где типы подсказок, отдельной группой под чертой.

Кнопка «−» никуда не делась — она скрыта. В разметке цели по-прежнему три кнопки, но ячейка .cell-error спрятана стилями. На счётчике этой кнопки держатся процент, «Отменить действие», восстановление после перезагрузки, замок холодной пробы и то, что уходит в таблицу и на сервер. Функция selectError() просто нажимает её за тераписта и подсвечивает «P/−». Удалить её из разметки — сломать всё перечисленное.

На кнопке «P/−» два числа: слева счётчик подсказок (это и есть настоящий счётчик кнопки), справа — сколько ошибок, в виде «2 (−)» (.err-count, заполняется в updatePercentages из скрытой кнопки). Разделены они не ради процента — ему подсказка и ошибка одинаковы, обе только в знаменателе, — а потому что это разные вещи клинически и потому что настоящие счётчики привязаны к своим кнопкам: из них восстанавливаются числа после перезагрузки и откатывается «Отменить действие».

В окне выбора есть ещё один исход — «/ Частично верный ответ». Технически это код в PROMPT_CODES, поэтому он жмёт ту же кнопку «P» и в проценте ведёт себя как подсказка (в знаменателе, не в числителе). В журнале ответов и в столбце «Подсказки» он уходит своим значком /, так что в таблице его видно отдельно.

Заодно с экрана убраны две вещи: график последних сессий (buildSparkline осталась в коде, но её результат больше не вставляют) и строка разбивки подсказок «P1 P4 …» (.prompt-details — display: none; данные собираются и уходят как раньше).

Тема хранится на планшете, а не у ребёнка. Она не переносится вместе с профилем и не попадает в резервную копию: у каждого тераписта своя. Если планшет сменили — тему выбирают заново.

Практика

Как безопасно править

Порядок действий, при котором ничего не ломается. Он не случайный: каждый шаг закрывает конкретную грабельку, на которую мы уже наступали.

  1. Правьте текст, а не логику. Самое безопасное: тексты подсказок в tour.js, памятка guide.html, стартовая страница index.html, шаблоны в templates.js. Эти файлы данные не трогают.
  2. Поднимите номер версии кэша. В sw.js строка const CACHE_NAME = "aba-checklist-v67"; → сделайте v68. Без этого планшеты не увидят изменений. Правило: меняли любой .html или .js — подняли номер.
  3. Выложите файлы через веб-GitHub. Add file → Upload files → перетащить → Commit. Выкладывать нужно и правленый файл, и sw.js.
  4. Проверьте на планшете при интернете. Закрыть приложение, открыть заново. Если изменений не видно — почти наверняка забыт шаг 2.
  5. Если стало хуже — откатите. В GitHub: файл → History → предыдущая версия → восстановить. И снова поднять номер кэша, иначе планшеты останутся на сломанной версии.

Чего лучше не делать без меня: переименовывать файлы страниц (сломаются ярлыки на домашних экранах планшетов), менять адрес Google-скрипта, трогать функции с данными — finalizeSession, realignProgressToBlocks, switchChild, deleteProtocol. Ошибка в них тихо портит данные, а это заметят через неделю.

Как проверить, что выложилось именно то

Откройте файл прямо на сайте, добавив имя к адресу: andr422.github.io/aisha/sw.js — увидите текст файла как он есть на бою. Так же можно посмотреть любой .js. Для страниц удобнее просто открыть приложение.
